# 08 - Face-track stabilizer (face-tracked reframe with a stable virtual camera)

Scope: the crop path of SKILL step 4: face detection, tracking, the subject per segment, a stabilised virtual camera (crop centre + size per frame), the preview / ffmpeg-path render, EffectCraft keys and the framing QC gate. Implemented by `scripts/face_track.py`; ref 01 §4 still sets the framing targets, ref 04 §2 the cut and jump-cut rules.

Refines SKILL step 4 (old: "smooth per ref 01: EMA, 8% W dead-zone, <= 3% W/s, no jitter", each job hand-rolled the tracker) and ref 01 §4 Smoothing (old: "a 1-euro filter or EMA (alpha ~ 0.08 at 30 fps)"). An EMA lags every real move by ~1/alpha frames (12 frames at alpha 0.08) and still passes detector noise; the offline path below has no lag and no noise.

## 1. Commands
```
python -P scripts/face_track.py run clips/NN/cut.mov --workdir clips/NN/face --size 1080x1440 --audio clips/NN/dialogue.wav [--cut-frames <splice frames>] [--jump-cuts F,..] [--subject auto|group|speaker] [--mode smooth|lock|steady] --render
```
`run` = `detect` -> cut sources -> `track` -> `stabilize` -> `qc` (-> `render` + `qc --video`). Each stage is also a subcommand (`track` takes the cut, subject, `--video`, `--audio`, `--size` and `--margin` flags; `stabilize` the camera flags); `selftest` runs the simulated checks (no media, no model). Run it on the clip intermediate (`cut.mov`, CFR, ref 03 §2), so frame k of the path is frame k of the edit.
- Cut sources are merged (union, recorded in `cuts_from`): `--cuts` (a cuts.py JSON or a list), `--cut-frames`, and `cuts.py` run on the same video (default in `run` and `track`; `--no-detect-cuts` turns it off). No source at all is a warning and qc P1 `no_cut_source`.
- `--audio dialogue.wav`: the clip's audio. `splice.py` writes `cut.mov` without audio, so `--subject speaker` needs it (no audio: exit 2), and `--render` muxes it into the preview. Bare `--audio` uses the video's own audio.

Outputs in the workdir: `det.json` (per-frame faces, a cache), `tracks.json` (segments, subject per frame, every tracked face per frame), `path.json` (per-frame crop `cx, cy, cw, ch` in source px + `effectcraft` keys), `qc/face_track_qc.json`, `qc/face_track_path.png` (camera path vs raw detections, dead zone, resets), `preview.mp4`. `qc path.json` alone writes to `<path dir>/qc/` too.

## 2. Method (adopted defaults; every number can be overridden by a flag)
1. **Detect.** YuNet (`cv2.FaceDetectorYN`, OpenCV Zoo `face_detection_yunet_2023mar.onnx`) on a <= 960 px wide copy streamed from ffmpeg (ref 04 §2 Optional), min face 4% H, score >= 0.6. The detector runs every frame at <= 30 fps, every 2nd frame above (`--every`). Every frame also gets Lucas-Kanade flow of the features inside each face box (inner 70%, forward-backward error < 0.7 px, median of >= 5 points): it carries boxes across skipped frames and is the precise motion signal of step 3.
   - Model search order: `--model`, env `CLIP_YUNET_MODEL` (when set, a missing file is exit 2, never silently replaced), then in each of `./models`, `./models/yunet`, `./`, `<skill>/models`, `~/models/yunet`, `~/models`, `~/.cache/opencv_zoo`, `~/.cache/opencv_zoo/face_detection_yunet`: the known names (2023mar, 2023mar_int8, 2022mar), else the newest-named `face_detection_yunet*.onnx`. `preflight.py` reports it (`yunet_model`) and test-loads it. No model: exit 2 with the download hint; a model that does not load (truncated download): exit 2 `model_bad`, before the video is read.
   - `det.json` is a cache keyed on the video (size + mtime), model, detector parameters and a detector version; a re-run reuses it (`cached: true`), so re-edits and stabiliser changes never re-detect (ref 05 §2).
2. **Track and subject.** Inside a shot, detections join tracks greedily (IoU >= 0.2 or centre distance <= 0.6 x face height). A miss of <= 0.5 s is held and filled linearly when the face returns; pieces split by a longer miss re-join when they start <= 1.5 s later at a plausible place and size (ours: height ratio 0.6-1.67, distance <= (1 + 2 x gap s) x face height). Tracks never cross a cut.
   - Subject per shot (`--subject`): `auto` = presence x size x (0.5 + 0.5 x centrality); `largest`; `central`; `group`; `speaker` = ref 04 §2 Optional active speaker (mouth-ROI motion vs |delta RMS| of the audio, Pearson r at lags -125..+45 ms, 2 s windows every 0.5 s, r >= 0.3 and >= 0.1 over the next face, held >= 2 s). A speaker switch inside a shot is a virtual cut: the camera snaps, it never pans between speakers.
   - Two people (SKILL step 4: a wider crop that holds both, never a split screen). A two-shot = tracks present >= 50% of the shot at >= 0.5 x the largest face, on screen together >= 30% of it (ours). It is framed as a group only when the members' union box (90th percentile) + margins fits the widest crop of the canvas (`track --size`): in `auto` automatically, in `group` on request. When it does not fit (a 9:16 crop of 16:9 is 31.6% of the width), `group` falls back to speaker cuts if audio is available, else to the leading face with a warning; `auto` frames the leading face, warns, and qc reports P1 `second_face_cropped`. Never two half faces.
   - Hand-off (ours): where the subject is gone for >= 0.5 s while another tracked face is on screen, that face takes over in a new segment (a virtual cut). This covers a missed cut, a face that jumps across the frame, and one person split into tracks that stitching could not join; the camera never holds on an empty spot.
   - A shot whose subject chain covers < 30% of it is `wide`: every face in it, the full-size crop, held still on the union of its faces when they fit, else following them with the smooth camera. Wide is not exempt from the gates.
3. **Fuse detector and flow (per axis, per segment).** Hampel rejection first (+-0.25 s, 3 sigma; with flow it runs on detections minus the integrated flow). A flagged sample that lies between its two neighbours (a fast move, not a spike) is kept, also by the refit. Then the least-squares face path: sum (p - z)^2 / sigma_d^2 over kept detections + sum (p_k - p_(k-1) - u_k)^2 / sigma_f^2 over flow steps + lambda_k (2nd difference)^2, one banded system; one refit drops residuals > max(3 x 1.4826 MAD, 2.5 sigma_d). sigma_d = max(1 px, 1.2% of the face height), sigma_f = 0.3 detection px (design choices). lambda_k is ~0 where flow covers both steps of frame k, else the detections-only Whittaker low-pass (cut-off `--lock-hz` 4 in lock, 6 Hz otherwise), so a gap in the flow never passes raw detector noise to the camera. With no detector frame at all, the path is anchored on the median box (never 0). Before the face first appears and after it leaves, the path holds.
4. **Crop size: one per segment** (ref 01 §4: no zoom inside a shot). Crop height = median face height / 0.24 (`--face-h`), at least the largest bound box + margins, at most the source (`min(H, W / aspect)`), and upscale <= 2.0 (`--max-upscale`, ref 01 Source scale). lock/steady keep 5% travel room each side (`--lock-room`) unless the face needs it: the room is given up before the face is cut. A same-camera jump cut (`--jump-cuts`) alternates the scale by 7% (`--jump-scale`; the other direction when the limits swallow it, a warning when < 4%) and pins frame 0 of the new segment within +-0.1% of the crop so the face keeps its canvas position (ref 04 §2 rule 5).
5. **Bounds.** Every frame: the bound box + 5% of the crop (`--margin`) inside the crop, the crop inside the source. Bound box = fused box + a smooth envelope (rolling max +-0.5 s, averaged +-0.25 s) of how far the raw box (detector, flow-carried or filled, unless rejected) sticks out of it beyond the segment's noise tolerance; noise tolerance = 3 x the robust std of the raw box edges around the fused box, at most half the margin (design choice). A real excursion is always held, but detector noise cannot push the camera frame by frame. Where face + margin cannot fit (source edge, face bigger than crop minus margins), the face box itself (margin 0) stays inside; a face bigger than the crop is centred.
6. **Camera path.**
   - `smooth` (default): L1-optimal path per axis (Grundmann, Kwatra, Essa 2011, "Auto-directed video stabilization with robust L1 optimal camera paths"), solved with `scipy.optimize.linprog` (HiGHS): minimise w_p |excess beyond the dead zone| + w_c |offset from target| + w1 |v| + w2 |a| + w3 |jerk| + w_v |speed above the cap|. The result is static holds joined by eased pans. Offline, so a pan starts before the move and finishes after it: no lag.
     - Dead zone 8% of the crop width (+-4%, ref 01 §4) and 6% of its height (ours: keeps the eyes inside ref 01's 22-35%). Weights in crop units: w_p 1/frame, w_c 0.02/frame, w1 = 0.3 s x fps, w2 = 0.05 x fps, w3 = 0.02 x fps^2, w_v = 4 x w1 (design choices, tuned on the tests in §4); `--strength` scales w1-w3.
     - Speed: soft cap 0.5 crop widths/s (`--max-speed`). Refines ref 01 §4 (old: "max pan speed 3% W per second"): with a hard 3%/s a 25%-of-crop lean takes 8 s to frame, so the face sits off-centre (or at the margin) for seconds; 0.5/s frames it in ~1 s with eased ends and still reads as a locked camera (87-97% static frames in §4).
     - The target point is the face centre in x and eyes at 28% H (`--eyes-y`) in y.
     - No scipy: a quadratic path (banded solve) + clamp, `method: l2_banded`.
   - `lock`: the crop centre follows the fused face path exactly, so camera and handheld shake are cancelled and the face stays pinned on the canvas (the background moves instead). Without flow it is a low-pass on the detections (`--lock-hz` 4) and qc cannot verify it (P1). At the source edge the crop cannot follow (clamped frames, qc P1 `lock_clamped`).
   - `steady` (ours): the smooth camera on the < 1 Hz part of the face path (Whittaker, ends odd-reflected so a cut does not bend it) plus the > 1 Hz part added back, weighted by the local flow density (full at >= 90% of the frames +-0.1 s, none at <= 50%), so it is zero where flow is missing and after the face leaves. Shake is cancelled like `lock`, deliberate moves are framed like `smooth`; without flow it is exactly the smooth camera.
7. **Resets.** Each cut, jump cut, speaker switch and hand-off starts a new segment: its path is solved alone, so the camera snaps on the cut frame and never pans across it. `--no-reset` exists only as the negative control.
8. **Outputs for both editing paths.**
   - EffectCraft: `path.json` `effectcraft` = one Position + uniform Scale key per frame for the footage layer (anchor at the layer centre, comp = canvas): scale = canvas H / crop H x 100%, position = canvas centre + scale x (layer centre - crop centre). Push-ins and freeze zooms go on a parent (ref 04 §2 rule 6), never on these keys.
   - ffmpeg fallback: `render` decodes the source at full size and applies a sub-pixel `warpAffine` crop + scale per frame (area-filtered first when downscaling), piped into libx264 with the YUV<->RGB matrix named on both sides and BT.709 tags. An integer `crop` per frame would add up to 1 px of quantisation jitter. `--overlay` draws the raw box (red), fused face (green) and margin box (yellow) for review only.

## 3. Gates (`qc`, exit 1 on any P0)
| Check | Rule | Rank |
|---|---|---|
| `face_outside_margin` | subject box (group / wide: the union of its faces) + 5% margin inside the crop on every frame with a subject, wide segments included; raw boxes may enter the margin by the segment's noise tolerance; a rejected detection is checked on its fused box (and reported P1 `rejected_box_outside` if the rejected box itself lies outside) | P0 |
| `face_outside_crop` | where face + margin cannot fit (`face_at_source_edge`, info), the face box itself (clipped to the source) inside the crop, unless it is bigger than the crop | P0 |
| `face_lost` | a tracked face (detector or flow box) exists but no face is fully inside the crop, for > 0.5 s (shorter: P1 `face_lost_brief`) | P0 |
| `other_face_cut` / `second_face_cropped` | a non-subject face cut by the crop edge / a second person (present >= 50% of the segment, >= 0.5 x the subject's size) outside the crop on > 50% of their frames (not in speaker segments) | P1 |
| `crop_outside_source` | crop inside the source on 100% of frames | P0 |
| `pan_across_cut` | 0 cuts where, within +-0.25 s, the camera moves > 1% of the crop width toward the other shot's framing beyond what the face itself does, or a listed cut is not a reset; lock/steady: on the camera minus the face motion it follows on purpose (clamped frames excluded) | P0 |
| `camera_jitter` (smooth, wide, static segments) | worst 0.5 s window of sqrt(max(0, -mean(d2_k . d2_k+1))) on the canvas <= 0.05% of the canvas width (0.54 px at 1080) | P0 |
| `camera_bump` (smooth) | a camera move of >= 0.5% W done in <= 0.25 s (a twitch, not an eased pan) | P1 |
| `canvas_jitter` (lock, steady) | the face on the canvas measured against the LK flow (canvas step = scale x (flow step - camera step)), integrated per run of flow frames, its part above 3 Hz (Whittaker high-pass), std <= 0.2% W; clamped frames excluded per axis | P0 |
| `output_face_jitter` (lock, steady; `--video`, automatic in `run --render`) | the face in the RENDERED clip (LK flow of the face region), same 3 Hz band, std <= 0.3% W per segment | P0 |
| `canvas_jitter_unverified` / `lock_clamped` | flow on < 80% of a lock/steady segment's face frames and no `--video` / crop held at the source edge on > 20% of them | P1 |
| `jump_anchor` / `jump_scale` | per jump cut: canvas face-centre shift per axis <= 0.625% W (P0; P1 when the source edge made the anchor impossible) / crop scale ratio in 0.90-0.96 or 1.04-1.11 (ref 04 §2 rule 5) | P0 / P1 |
| `no_cut_source` | the track stage had no cut source | P1 |
| `face_height` / `eyes_y` / `centre_x` | per-segment medians 20-30% H / 22-35% H / 40-60% W on face/group segments >= 1 s (ref 05 §1 Framing by shot medians) | P0; P1 when the crop size is limited by the source/upscale, the subject is a group, or the ideal crop would leave the source on > 50% of the segment |

Also reported: raw vs camera 2nd-difference RMS on the same detector frames and the reduction factor, plain camera 2nd-difference RMS, max speed (crop widths/s), static frames %, rejected detections (and how many were gated on the fused box), clamped frames, per-segment flow coverage and the face's own motion in the 3 Hz band.

Why these metrics (design choices, tested in §4): 1.4826 x median |2nd difference| scored a smooth sway as jitter (it measures acceleration) and ignored noise on < 50% of the frames; the lag-1 product of 2nd differences is negative only for oscillation, so sways read 0 and a noisy stretch fails whatever share of the clip it covers. The lock/steady gate used to compare the fused face with a camera built from that same fused face, so it could not fail; the flow-based measure is independent of the detector path. It cannot see noise in the flow itself (the camera then follows the same noise): the rendered-output measure can, so `run --render` is the full check for lock/steady.

## 5. Use in the pipeline
- Default `smooth` for podcasts, interviews and tripod shots; `steady` for handheld / IRL / walking shots; `lock` when the face must not move at all (a face-pinned reaction, a meme zoom base). The mode is a per-request choice; if lock/steady fail `canvas_jitter` / `output_face_jitter` (fast action, face at the source edge, little flow), use smooth for that clip.
- Cuts: run on `cut.mov` and let `cuts.py` run on it (what `run` does by default), so its reset frames are in the edit's frames. Add every splice frame of the cut list (the frames where `cut.mov` joins two kept spans; they are in the edit's frames already) with `--cut-frames`; they merge with the detected cuts. `cuts.py --start/--end` frames of the source window are NOT edit frames after any removed span: remap them through the cut list's remap first, or do not pass them. Same-camera joins go to `--jump-cuts`.
- Two faces in one shot: `auto` frames a two-shot as a group when both fit the canvas; `--subject speaker --audio clips/NN/dialogue.wav` cuts between speakers when they do not (9:16 of a 16:9 two-shot usually does not).
- Review `qc/face_track_path.png` and the preview with `--overlay` once per clip; fix every P0 before captions (caption face avoidance reads the same crop path).

## 6. Open issues / NOT ADOPTED
- `cuts.py` can read a fast whole-frame move (whip pan, a camera swing of ~40 px/frame at 1080p) as a hard cut; the face tracker then resets there, which is safe (a snap, never a pan) but changes framing mid-move. Merged cut sources cannot remove such a cut; use `--no-detect-cuts` with an explicit list when that happens.
- A face that exits the frame very fast is chased (the bounds keep it inside until it is gone): a jerk that `camera_jitter` reports. Letting a subject exit is not implemented.
- Fast action with profile turns fragments tracks (frontal detector); stitching joins gaps <= 1.5 s, hand-offs cover the rest with virtual cuts. A profile detector (ref 04 §2 Optional) is not added: cv2 5.0.0 ships no Haar cascades and no second ONNX model is bundled.
- Faces inside pasted-in pictures (thumbnails, screen recordings) are tracked like live faces; `auto` usually prefers the live face by size and centrality, and a pasted face can take over by hand-off when the live face is absent. There is no picture-in-picture filter yet.
- Noisy LK flow is only caught by the rendered-output gate (`run --render`); an estimate of flow noise from the detections was tried and rejected (it read normal head motion on a real talking head as 3.5 px/step of noise).
- Roll (head or camera rotation) is not stabilised; lock/steady cancel translation only.
- `--subject group` needs `track --size` to match the canvas (`run` passes it); `stabilize` warns when the aspects differ.
- NOT ADOPTED: ref 01's EMA / 1-euro smoothing (lags real moves, passes noise) and its hard 3% W/s pan cap (see §2.6); kept as the "locked camera" intent through the dead zone, the L1 holds and the soft speed cap.
